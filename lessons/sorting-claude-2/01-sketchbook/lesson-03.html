Lesson 3

How far is an array from sorted, and what does a local fix buy?

Builds on Lessons 1–2 · about 45 minutes

Where we are

Lesson 2 ended with an uncomfortable fact. Repeatedly selecting the smallest remaining element always makes exactly $\binom{n}{2} = \frac{n(n-1)}{2}$ comparisons, even when the array is already sorted. Yet Lesson 1 showed that merely checking whether an array is sorted takes only $n-1$. So the open question was:

Open question.

Can an algorithm's cost depend on how unsorted its input actually is?

?

Results this lesson relies on:

  • L1. Verifying that $n$ distinct keys are sorted needs exactly $n-1$ comparisons. [proof]
  • L2. Repeated selection makes exactly $n(n-1)/2$ comparisons on every input. [proof]
  • L0. Keys are distinct, and we learn about them only by comparing them. (Assumption.)

1. A number for disorder

To make cost depend on how unsorted the input is, we first need a precise measure of how unsorted it is. Two obvious candidates fail, and seeing why tells us what the right measure must capture.

Candidate A: count the elements that are not in their final position. The arrays $[2,1,4,3,6,5]$ and $[6,5,4,3,2,1]$ both score 6: every element is misplaced. But the first is fixed by three swaps of neighbours, while the second, as we'll see, needs fifteen. The measure can't tell them apart.

Candidate B: count adjacent descents, positions $k$ with $a[k] > a[k+1]$. Now $[2,3,4,5,6,1]$ scores 1 and $[2,1,4,3,6,5]$ scores 3. Yet in the first array the 1 must travel past five elements, one neighbour at a time. The measure ranks them the wrong way round.

Both candidates look at positions one at a time, or at neighbours. But order is a relation between pairs of elements. So count pairs.

Definition (inversion).

An inversion in an array $a$ is a pair of positions $(i, j)$ with $i < j$ and $a[i] > a[j]$: two elements that appear in the wrong relative order. Write $I(a)$ for the number of inversions of $a$.

Two facts follow directly from the definition:

  • $I(a) = 0$ exactly when $a$ is sorted. [proof] If no pair is out of order, then no adjacent pair is, and that is what sorted means (Lesson 1). Conversely, in a sorted array transitivity puts every pair in order.
  • $I(a) \le \binom{n}{2}$, with equality exactly for the reversed array. [proof] There are only $\binom{n}{2}$ pairs, and all of them are inverted only when the array runs in decreasing order.

So $I$ ranges from $0$ to $\frac{n(n-1)}{2}$. Those are exactly the two costs we've met so far: verification and repeated selection. That's a hint, not yet an argument. [intuition]

2. What does one local fix change?

The cheapest physical repair is to swap two neighbours. Suppose $a[k] > a[k+1]$, an adjacent inversion, and we swap them.

Lemma 1.

Swapping an adjacent inverted pair reduces $I$ by exactly one. [proof]

Proof

Ask which pairs can change status. A pair's status depends only on the relative order of its two elements. Take any pair other than the two swapped elements. If neither of its elements sits at position $k$ or $k+1$, nothing about it moved. If one of them does, the other is either to the left of both positions or to the right of both, so the two stay on the same side of each other after the swap. Only the swapped pair itself changes, and it goes from inverted to not inverted. ∎

The same argument shows that swapping a non-inverted neighbouring pair creates exactly one inversion. Either way, one adjacent swap changes $I$ by exactly one.

Theorem 1.

Any algorithm that rearranges elements only by swapping neighbours needs at least $I(a)$ swaps on input $a$. On the reversed array that is $\frac{n(n-1)}{2}$. [proof]

Proof

Each swap changes $I$ by exactly one. We start at $I(a)$ and must reach $0$. ∎

Note.

Theorem 1 is a lower bound on a class of algorithms: those that move elements only between neighbours. It says nothing yet about sorting in general. An algorithm allowed to move an element far in a single step is not covered. Keep that loophole in mind.

3. Building an algorithm from the lemma

Lemma 1 suggests a goal: never waste a swap. If every swap removes an inversion, the total is exactly $I(a)$, the minimum Theorem 1 allows. The difficulty is finding an inverted neighbour without rescanning the array after every swap.

Some structure helps. Keep a prefix $a[0:i]$ sorted. A new element $a[i]$ is inverted with exactly the prefix elements larger than it, and because the prefix is sorted those elements sit in a block immediately to its left. Swapping $a[i]$ leftward while its left neighbour is larger removes those inversions one at a time, and stops at the first neighbour that is smaller.

This procedure is called insertion sort: each step inserts the next element into the sorted prefix.

What stays true from pass to pass? A tempting guess: the prefix holds the smallest elements. That is false. After $i = 1$ the prefix is $[1, 4]$, but $2$ and $3$ are both smaller than $4$. What the prefix actually holds is the first elements of the input, rearranged into sorted order. That is the invariant.

Invariant.

At the start of the iteration with index $i$:

(a) $a[0:i]$ is sorted; (b) $a[0:i]$ is a rearrangement of the original first $i$ elements; (c) $a[i:n]$ is untouched.

Why do we need (b) and (c)? Without them, an "algorithm" that overwrote every element with zero would satisfy (a). Sorting means ordered and a permutation of the input (Lesson 0).

Theorem 2.

insertion_sort returns its input in sorted order. [proof]

Proof

Initialization. When $i = 1$, the prefix $a[0:1]$ has one element, so it is sorted, and nothing has moved.

Maintenance. We need to know what holds while the key, the original value of $a[i]$, travels left. The elements it has passed form a block to its right, and all of them are larger than it. That gives an inner invariant: $a[0:j]$ is sorted; $a[j+1:i+1]$ is sorted; and every element of $a[j+1:i+1]$ is larger than the key at $a[j]$. It holds when $j = i$, because the block is empty. A swap moves one larger element from the left of the key to the front of the block, and since the prefix was sorted, that element is no larger than anything already in the block. The loop stops either because $j = 0$, or because $a[j-1] < a[j]$ (keys are distinct). In both cases $a[0:j]$, then the key, then $a[j+1:i+1]$ are in order, so $a[0:i+1]$ is sorted: (a) holds for $i+1$. Swaps only exchange elements, so (b) holds, and positions from $i+1$ on were never touched, so (c) holds.

Termination. The inner loop's $j$ strictly decreases and cannot go below $0$. The outer loop runs $n - 1$ times. At exit $i = n$, so (a) and (b) together say the whole array is a sorted rearrangement of the input. ∎

5. What it costs

We count two things separately: swaps, which move elements, and comparisons, which gather information. Lesson 2 showed that these can behave very differently.

Swaps. Every swap removes one inversion, and the algorithm stops when none are left, so it makes exactly $I(a)$ swaps. By Theorem 1, no adjacent-swap algorithm can do better. [proof]

Comparisons. Each test a[j - 1] > a[j] that comes out true is followed by a swap, which accounts for $I(a)$ comparisons. Each of the $n - 1$ insertions also ends with at most one test that comes out false. There is none when the key reaches position $0$, because then j > 0 fails first and Python never evaluates the comparison. So, writing $C(a)$ for the number of comparisons,

$$I(a) \;\le\; C(a) \;\le\; I(a) + (n-1).$$
[proof]

Read it back: the cost is the disorder, plus at most one extra comparison per element. On sorted input, $I = 0$ and the algorithm makes $n - 1$ comparisons, exactly Lesson 1's cost for merely verifying sortedness. So the answer to the open question is yes. An algorithm whose cost tracks how unsorted its input is is called adaptive.

Worst case. On the reversed array, $I = \frac{n(n-1)}{2}$, and every key travels all the way to position $0$, so no test ever comes out false. Hence $C = \frac{n(n-1)}{2}$. [proof]

Average case. What about a "typical" input? To make "typical" precise we must choose a distribution. Assume every ordering of the $n$ distinct keys is equally likely: a uniformly random permutation. That is an assumption about the inputs, so the result will be an average case, not a guarantee for any particular input.

Why we need a tool here: averaging $I$ directly over all $n!$ orderings is hopeless for large $n$. But $I$ is a sum of small pieces, one for each pair, and the average of a sum is the sum of the averages. That is linearity of expectation, and it needs no independence between the pieces.

$$I = \sum_{i<j} X_{ij}, \qquad X_{ij} = \begin{cases} 1 & \text{if } a[i] > a[j],\\ 0 & \text{otherwise.}\end{cases}$$

Each pair is inverted with probability one half. Swapping the values at positions $i$ and $j$ pairs every ordering in which the pair is inverted with exactly one in which it isn't. So

$$\mathbb{E}[X_{ij}] = \Pr\big[a[i] > a[j]\big] = \tfrac12, \qquad \mathbb{E}[I] = \sum_{i<j} \tfrac12 = \binom{n}{2}\cdot\tfrac12 = \frac{n(n-1)}{4}.$$
[proof]

Sanity check. For $n = 3$ the six orderings have $0, 1, 1, 2, 2, 3$ inversions. Their average is $9/6 = 1.5 = \frac{3 \cdot 2}{4}$.

So on average insertion sort does about half its worst-case work, which is still $\Theta(n^2)$. And by Theorem 1, every adjacent-swap algorithm needs at least $\frac{n(n-1)}{4}$ swaps on average.

Going deeper: the exact average number of comparisons

The bound $C \le I + (n-1)$ overcounts by one for each key that travels all the way to the front: for that key, the loop ends on j > 0 without a final comparison. Position $i$ holds a new minimum (a key smaller than everything before it) with probability $\frac{1}{i+1}$, since each of the first $i+1$ keys is equally likely to be the smallest of them. Summing over $i = 1, \dots, n-1$, the expected number of such keys is $H_n - 1$, where $H_n = 1 + \frac12 + \dots + \frac1n$. Therefore

$$\mathbb{E}[C] \;=\; \frac{n(n-1)}{4} + (n-1) - (H_n - 1) \;=\; \frac{n(n-1)}{4} + n - H_n.$$
[proof]

For $n = 3$ this gives $1.5 + 3 - \frac{11}{6} = \frac{8}{3}$, which matches a direct count over all six orderings.

6. What does the algorithm know?

One more view. After each comparison, what does insertion sort actually know? Exactly the relations it has observed, plus whatever follows from them by transitivity. The figure draws that knowledge: a line from $x$ up to $y$ means "known: $x < y$". Beside it is the number of orderings of the five keys still consistent with that knowledge.

The count starts at $5! = 120$ and must reach $1$. Insertion sort gets there in $8$ comparisons. But notice how unevenly they work. The fourth comparison, $4$ vs $5$, cuts the count from $20$ to $5$, while the fifth, $2$ vs $5$, only takes it from $5$ to $4$. Since $\log_2 120 \approx 6.9$, it's natural to ask whether $7$ well-chosen comparisons could always suffice, and what "well-chosen" would mean. That is Lesson 5's question. [intuition]

7. Checkpoint

Ledger

Established

  • $I(a)$ measures disorder: it is $0$ exactly when $a$ is sorted, and at most $\binom{n}{2}$, reached exactly by the reversed array. [proof]
  • Swapping an adjacent inverted pair removes exactly one inversion. [proof]
  • Any adjacent-swap algorithm needs at least $I(a)$ swaps: $\frac{n(n-1)}{2}$ in the worst case and $\frac{n(n-1)}{4}$ on average. This is a bound on a class of algorithms. [proof]
  • Insertion sort is correct. Invariant: $a[0:i]$ is a sorted rearrangement of the first $i$ input elements. [proof]
  • Insertion sort makes exactly $I(a)$ swaps and $I(a) \le C(a) \le I(a) + n - 1$ comparisons: $n - 1$ at best, $\frac{n(n-1)}{2}$ at worst, and $\frac{n(n-1)}{4} + n - H_n$ on average over uniformly random permutations. [proof]
  • Measured averages agree with the exact formula. [empirical]

Assumptions in force

distinct keys; information only through comparisons; uniformly random permutations for every average-case statement.

Lenses in use

Knowledge, glimpsed in Figure 4. Movement, new: Theorem 1 is a bound on movement, not on information.

Reasoning tools acquired

finding an invariant by tracing passes and rejecting a false candidate; indicator variables and linearity of expectation; bounding a whole class of algorithms by a quantity each step can change by at most one.
