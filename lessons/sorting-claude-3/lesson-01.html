Lesson 1

What does it mean for things to be in order?

Stage 0 · Foundations

Where we are

This is the first lesson. Every later lesson asks how cheaply things can be put in order, and why it costs what it costs. Before we can talk about cost, we have to know exactly what we are producing. “Put these in order” sounds obvious. This lesson shows that it is not, by looking at four requests that sound alike and behave completely differently, and it finds the few properties of a rule that decide what a correct answer is, whether one exists, and how many there are.

Depends on: nothing. Background assumed: algebra, logarithms, proof by induction.

Prerequisite check

The statement “for every x, if P(x) then Q(x)” is false. What does that tell you?

  • There is at least one x for which P(x) is true and Q(x) is false.
    A “for every … if … then” statement fails exactly when one counterexample exists: an x satisfying the condition but not the conclusion. Counterexamples of this shape are how we will show that a proof needs an assumption.
  • P(x) is false for every x.
    If P(x) were false for every x, the statement would be (vacuously) true: there would be no x to break it. To break it you need an x where P holds and Q fails.
  • There is an x for which Q(x) is true and P(x) is false.
    That x satisfies the statement: when the condition P(x) is false, the “if … then” has nothing to check. The direction matters: the condition must hold and the conclusion fail.
  • Q(x) is false for every x.
    Too strong. One x with P(x) true and Q(x) false is enough to make the statement false; nothing is said about the other x.

You want to prove a statement S(n) for every n ≥ 1 by induction. What do you need to show?

  • S(1), and that S(k) implies S(k+1) for every k ≥ 1.
    Base case and step. In this lesson we will often use the step in the form “remove one element and apply the statement to the remaining n − 1”.
  • S(1) and S(2).
    Checking cases is not a proof for all n. The step S(k) ⇒ S(k+1) is what carries the truth from each n to the next.
  • That S(k+1) implies S(k) for every k.
    This runs the implication backwards: it lets you go down from a large n, but nothing starts the chain at n = 1 and moves it up.
  • S(n) for n = 1, …, 10, chosen at random.
    Any finite number of checks leaves infinitely many n unproved. Induction replaces the checks with one general step.
Going deeper · Notation primer
  • A set is written with braces: \(\{a, b, c\}\). Order and repetition inside braces do not matter.
  • An ordered pair \((x, y)\) is different from \((y, x)\) when \(x \neq y\). Relations are sets of ordered pairs.
  • “iff” means “if and only if”: each side implies the other.
  • Negating “for every x, if P(x) then Q(x)” gives “for some x, P(x) and not Q(x)”.
  • Induction on n: prove S(1), then prove S(k) ⇒ S(k+1). Strong induction: prove S(n) assuming S(m) for every m < n. We will use both.
  • \(n!\) (“n factorial”) is \(1 \cdot 2 \cdots n\), with \(0! = 1\).

01Four requests

Here are four requests. Each one sounds like “put these in order”.

  • (A) Put the numbers 7, 2, 9, 4 in increasing order.
  • (B) Put four people in order of age, youngest first: Ana (30), Ben (25), Cy (30), Dee (22).
  • (C) Put four tasks in an order in which every task comes after the tasks it needs: a = write the code; b = write the tests; c = run the tests (needs a and b); d = review the tests (needs b).
  • (D) Put rock, paper and scissors in an order in which, whenever one item beats another, the winner comes first. (Rock beats scissors, scissors beats paper, paper beats rock.)

Before reading on, decide how many correct answers each request has. It may be exactly one, more than one, or none at all.

Predict first

For each request, how many correct answers are there?

  • (A) numbers 7, 2, 9, 4
    Only 2 can stand first: any other number has a smaller one that would have to come before it. After 2, only 4 can come next, then only 7, then 9. No step offers a choice, so 2, 4, 7, 9 is the only answer.
    Try to build a second answer. The first number must have no smaller number after it, so it must be 2; the same argument then fixes 4, 7 and 9 in turn. There is never a choice.
    2, 4, 7, 9 satisfies the request.
  • (B) people by age
    Dee (22) must come first and Ben (25) second. Ana and Cy are both 30: neither is younger, so the request lets either one come third. Two answers: Dee, Ben, Ana, Cy and Dee, Ben, Cy, Ana.
    Who comes third, Ana or Cy? Age does not separate them and the request gives no other rule, so both choices are correct: two answers.
    Dee, Ben, Ana, Cy satisfies the request.
  • (C) tasks
    a and b need nothing, so either can come first, and further choices follow. There are five answers: abcd, abdc, bacd, badc, bdac. The reveal below shows how they arise.
    a and b both need nothing, so either can come first: there are at least two answers.
    a, b, c, d satisfies every requirement.
  • (D) rock, paper, scissors
    Whatever comes first must not be beaten by anything, because the winner would have to come before it. But rock is beaten by paper, paper by scissors and scissors by rock. Nothing can come first, so there is no answer.
    Which item could come first? It would have to come before the item that beats it, and every item is beaten by one of the others. Nothing can come first, so no order works.

One, two, five and none. All four counts come from asking one question, over and over:

Which items can go first?

An item can go first when the request does not require anything else to come before it. Put one such item first, set it aside, and ask the question again about the items that remain. Each run of choices builds one correct answer, and different runs build different answers, so counting the answers means counting the ways to keep choosing intuition (section 04 turns this into a proof). Fig. 1 does the counting for all four requests.

Here is the same reasoning in words.

  • (A) Only 2 can go first: every other number has a smaller one that would have to come before it. Of the rest, only 4 can go next, then only 7, then 9. There is exactly one candidate at every step, so there is exactly one answer.
  • (B) Only Dee can go first, since everyone else is older than someone. Then only Ben. Then Ana and Cy can both go next, because neither is younger than the other; whichever goes third, the other goes fourth. One step offers two candidates, so there are two answers.
  • (C) Tasks a and b need nothing, so both can go first. If a goes first, only b can go next (c and d both need b), and then c and d can go in either order: two answers. If b goes first, both a and d can go next (d needed only b). After b, a, again c and d can go in either order: two more answers. After b, d, only a can go next (c still needs a), then c: one more answer. That makes 2 + 2 + 1 = five.
  • (D) Nothing can go first. Whatever we try is beaten by something, and the winner would have to come before it: rock needs paper before it, paper needs scissors, scissors needs rock. With no possible first item there is no answer at all.

So the counts are explained by the candidates at each step: exactly one every time gives one answer; more than one at some step makes the answers branch; none at some step leaves no answer at all.

Notice what did not matter: what the items are. Numbers, people, tasks and hand shapes play no role. What matters is the rule each request uses to say which item must come before which. The rest of this lesson studies those rules: how a rule about pairs decides a whole row, and how to write one down precisely (§02); which rules allow any answer at all (§03); how to picture a rule and count its answers (§04); which rules allow exactly one answer (§05); and how ties fit in (§06). The properties we find are exactly the ones every sorting algorithm in this course will be allowed to assume.

02From two items to a whole row

Start with the smallest case: two items. Ordering two items is easy, because each request tells us directly which one goes first. Of 7 and 4, the smaller: 4, 7. Of Ben and Ana, the younger: Ben, Ana. Of tasks a and c, the one that c needs: a, c. Of rock and scissors, the winner: rock, scissors. Sometimes the request does not care: Ana and Cy are the same age, so Ana, Cy and Cy, Ana are both fine, and so are a, b and b, a. For any two items, then, a request gives one of three verdicts: this one first, that one first, or it does not matter.

What about all four items at once? A row of four items is not a new kind of object: it is six pairs at once. Every two items in a row stand in some order, the left one first. The row Dee, Ben, Ana, Cy, for instance, puts Dee before Ben, Dee before Ana, Dee before Cy, Ben before Ana, Ben before Cy, and Ana before Cy. The row obeys the request exactly when each of these six pairs stands in an order the request allows. So the verdicts on pairs decide every row, and nothing else is needed: a request is completely described by its rule for pairs. That is why the four outcomes of §01 can only come from these rules.

Why, then, is a whole row harder than a single pair? Because in a row the pairs are not independent. Once \(x\) stands before \(y\) and \(y\) stands before \(z\), the row has already put \(x\) before \(z\), whether or not the rule wants that. Each requirement is easy to meet on its own; the question is whether all of them can be met in one row at the same time, and in how many ways. In (D) they cannot. Rock before scissors is easy, scissors before paper is easy, and paper before rock is easy; but a row that meets the first two has already put rock before paper, and so it breaks the third. In (B) and (C) they can, and the pairs on which the request does not care leave room for several rows. Those are the questions for the rest of this lesson. To answer them, we first need a precise way to write a rule down.

The most direct way is to list the rule’s “first” verdicts: every pair \((x, y)\) for which \(x\) must come before \(y\). For request (B) the list is

(Dee, Ben), (Dee, Ana), (Dee, Cy), (Ben, Ana), (Ben, Cy).

This list is the whole rule, because all three verdicts can be read off it. Must Ben come before Cy? (Ben, Cy) is on the list: yes. Must Cy come before Ben? (Cy, Ben) is not on the list, but (Ben, Cy) is: no, Ben comes first. Must Ana come before Cy? Neither (Ana, Cy) nor (Cy, Ana) is on the list: it does not matter. The order inside each pair carries the meaning: (Ben, Ana) says Ben goes first, and (Ana, Ben) would say the opposite. So the pairs on the list are ordered pairs. Table 1 writes all four rules this way.

A list of ordered pairs like these is what mathematics calls a relation. We will say “\((x, y)\) is on the list” constantly, so it gets a symbol.

Definition (relation)

A relation on a set \(X\) is a set of ordered pairs \((x, y)\) with \(x, y \in X\): the list of pairs for which a rule answers “yes”. We write \(x \prec y\) when \((x, y)\) is in the relation, and read it “\(x\) must come before \(y\)”.

The symbol \(\prec\) is a curved \(<\) on purpose: it plays the role of \(<\) for any rule, not only for numbers. Lists grow quickly (\(n\) items have \(n(n-1)\) ordered pairs of distinct items), so in practice a relation is described by the rule that produces its list:

  • (A) \(x \prec y\) iff \(x < y\).
  • (B) \(p \prec q\) iff \(p\) is younger than \(q\).
  • (C) \(x \prec y\) iff \(y\) needs \(x\), directly or through other tasks. (Here d needs b, and c needs a and b. No task is needed only through another, so the list is exactly the three pairs of Table 1.)
  • (D) \(x \prec y\) iff \(x\) beats \(y\).

The third verdict, “it does not matter”, is a pair that appears on the list in neither order: neither \(p \prec q\) nor \(q \prec p\). Ana and Cy form such a pair (neither is younger than the other), and so do tasks a and b (neither needs the other). Keep these unconstrained pairs in mind: they are exactly where the choices of §01 came from.

Now the verdict on a whole row can be made precise. A row obeys a request when every pair in it stands in an order the rule allows. In a row, two items can stand in one of three ways:

  • in the required order: fine;
  • unconstrained: the rule says nothing about them, so either order is fine (Ana and Cy);
  • out of order: the later item is required to come before the earlier one. Only this breaks the request.

And this applies to every pair in the row, not only to neighbours: Dee must come before Cy wherever the two stand. So a row is correct exactly when no pair, anywhere in it, is out of order.

Definition (sorted arrangement)

An arrangement \(x_0, x_1, \ldots, x_{n-1}\) of the elements is sorted with respect to \(\prec\) if no pair is out of order: there are no positions \(i < j\) with \(x_j \prec x_i\). A pair of positions \(i < j\) with \(x_j \prec x_i\) is called an out-of-order pair.

Check it on (B). In Dee, Ben, Ana, Cy, no later person is younger than an earlier one, so the row is sorted. Swapping Ana and Cy keeps it sorted, because that pair is unconstrained. Those are exactly the two answers of §01. From now on, “a correct answer to a request” has a precise meaning: a sorted arrangement with respect to the request’s relation.

Checking a row this way means looking at every pair in it: six pairs for four items, and \(n(n-1)/2\) for \(n\) items. A tempting shortcut is to look only at neighbours, and demand that each item come before the next one.

Predict first

Under the shortcut (each person must be strictly younger than the next person in the row), how many rows of request (B) pass?

  • Two: the two correct answers.
    Those two rows are correct answers to the request, but the shortcut is stricter than the request. See below.
  • One.
    Which one would pass? Try Dee, Ben, Ana, Cy and check its last step, from Ana to Cy.
  • None.
    Right. See why below.

None. The shortcut asks every person to be strictly younger than the next, so the ages must strictly increase along the whole row. Ana and Cy share an age, and a strictly increasing row cannot repeat one. Even Dee, Ben, Ana, Cy fails, at its last step from 30 to 30, although it is a correct answer to the request.

The shortcut does no better on (C). There it would need four tasks in a row, each needed by the next, and the longest such chain in (C) has only two tasks (for example b, then d).

The shortcut fails because it demands “before” where the request only forbids “after”: it treats “it does not matter” as a failure. Yet checking neighbours is so much cheaper than checking every pair that it is worth asking whether some corrected version of the shortcut can be trusted. §05 and §06 answer that question. Meanwhile, Fig. 2 shows the full test at work on a row of numbers that fails it.

How many out-of-order pairs does 7, 2, 9, 4 have under \(<\)?

(7, 2), (7, 4) and (9, 4). Fig. 2 draws all three.
You probably checked only neighbours: (7, 2) and (9, 4). The definition looks at every pair of positions, and 7 and 4 are out of order even though they are not adjacent.
6 is the number of pairs of positions, \(\binom{4}{2}\). Only the pairs where the later number is smaller count.
List the 6 pairs of positions and keep those where the later number is smaller than the earlier one.
Go through the positions from left to right; for each number, count the numbers after it that are smaller.

For each number, count the smaller numbers that come after it: 7 → 2 and 4 (two pairs); 2 → none; 9 → 4 (one pair); 4 → nothing after it. Total 2 + 0 + 1 = 3.

03Which rules allow an answer at all?

Request (D) has no sorted arrangement. A sorting algorithm handed such a rule could not possibly succeed, so before anything else we want to know which relations admit at least one sorted arrangement.

In §01, (D) failed because nothing could go first, and §02 watched its three requirements collide. Both have the same cause. Follow the rule from rock: rock must come before scissors, scissors before paper, and paper before rock. The requirements run in a loop and come back to where they started. On a loop, no item can go first, because the item before it on the loop must come earlier still. A loop of requirements is called a cycle.

Definition (cycle)

A cycle is a sequence of distinct elements \(x_1, x_2, \ldots, x_k\) with \(k \ge 2\) and \(x_1 \prec x_2 \prec \cdots \prec x_k \prec x_1\).

What we saw for rock, paper and scissors holds for every cycle, in any relation, however many other elements there are:

Lemma 1 (a cycle forbids order)

If \(\prec\) has a cycle, no arrangement is sorted.

Proof

Take any arrangement and look at the elements of the cycle. One of them, say \(x_m\), sits at the earliest position among them. Its predecessor on the cycle (\(x_{m-1}\), or \(x_k\) if \(m = 1\)) satisfies \(x_{m-1} \prec x_m\) and sits at a later position. That is an out-of-order pair. Since the arrangement was arbitrary, none is sorted.

So the rules worth sorting by are rules without cycles. Can we recognise them by simple properties, rather than by searching every rule for loops? Look at where every request ends up: in a row. A row has its own “comes before”: position 2 comes before position 5. That relation has two properties nobody would question. Nothing comes before itself. And “before” chains: if \(i\) comes before \(j\) and \(j\) comes before \(k\), then \(i\) comes before \(k\).

It is natural to ask the same two things of a rule. No row can put an item before itself, so a rule that demanded it could never be met. And a row that meets two requirements, \(x\) before \(y\) and \(y\) before \(z\), automatically meets a third, \(x\) before \(z\); asking the rule to state such consequences explicitly costs nothing. Both properties have names, and so does a relation that has both.

Definition (strict partial order)

A relation \(\prec\) on \(X\) is a strict partial order if it is

  • irreflexive: \(x \prec x\) holds for no \(x\);
  • transitive: \(x \prec y\) and \(y \prec z\) imply \(x \prec z\).

“Strict” because nothing comes before itself, as in \(<\) rather than \(\le\). “Partial” because the rule may leave some pairs unconstrained: it settles only part of the order.

Two consequences follow at once. The first: such a rule never demands both orders of the same pair.

Lemma 2 (asymmetry)

In a strict partial order, \(x \prec y\) and \(y \prec x\) never both hold.

Proof

If both held, transitivity would give \(x \prec x\), which irreflexivity forbids.

The second is the one we were after: the two properties rule out loops of any length.

Lemma 3 (no cycles)

A strict partial order has no cycles.

Proof

Suppose \(x_1 \prec x_2 \prec \cdots \prec x_k \prec x_1\). Applying transitivity along the cycle (induction on \(j\) shows \(x_1 \prec x_j\) for every \(j \ge 2\)) gives \(x_1 \prec x_k\), and with \(x_k \prec x_1\) once more, \(x_1 \prec x_1\). Irreflexivity forbids it.

Each property does its own job. Transitivity alone is not enough: the relation “\(x \prec y\) for every \(x\) and \(y\)” is transitive and full of cycles. Irreflexivity alone is not enough either: rock–paper–scissors is irreflexive (nothing beats itself) and is one big cycle. Together they make loops impossible.

Now check the four requests against the definition:

  • (A) \(<\) on numbers is irreflexive and transitive.
  • (B) “younger than”: nobody is younger than themselves, and someone younger than a younger person is younger still.
  • (C) “needed directly or through other tasks” is transitive by its wording, and irreflexive as long as no task needs itself. A task that needed itself, directly or through others, would be a cycle: the “circular dependency” error that build tools report.
  • (D) “beats” is not transitive: rock beats scissors and scissors beats paper, but rock does not beat paper.

So (A), (B) and (C) are strict partial orders, and (D), the one request with no answer, is not.

Notice what has been proved so far, and what has not. A rule with a cycle has no answer (Lemma 1), and a strict partial order has no cycle (Lemma 3). That removes the one obstacle we know of. It does not yet show that every strict partial order has an answer: some other obstacle might exist. §04 shows that none does.

Common question · Why strict \(\prec\) instead of \(\le\)?

Because “strictly before?” is the question a sorting algorithm asks; Python’s sort asks only a < b. The non-strict version also misbehaves with ties: ordering people by “age \(\le\)” gives Ana \(\le\) Cy and Cy \(\le\) Ana although Ana \(\neq\) Cy, so it is not a partial order in the usual (antisymmetric) sense. The strict form handles ties cleanly: Ana and Cy are simply unrelated.

Before going on, try the two properties on relations of your own.

Checkpoint 1

Q1

Which of these relations is a strict partial order?

  • \(\le\) on the integers
    \(\le\) is not irreflexive: \(3 \le 3\). It is the non-strict cousin of \(<\). The strict version, \(<\), is a strict partial order (in fact a total one).
  • “is a proper subset of” on the subsets of \(\{1, 2, 3\}\)
    No set is a proper subset of itself, and \(A \subsetneq B \subsetneq C\) gives \(A \subsetneq C\). It is not total: \(\{1\}\) and \(\{2\}\) are unrelated. Keep it as an example of a partial order with many unrelated pairs.
  • “beats” in rock–paper–scissors
    Irreflexive, but not transitive: rock beats scissors, scissors beats paper, yet rock does not beat paper. Lemma 1 then shows no arrangement can respect it.
  • “is a sibling of” on people
    Nobody is their own sibling, so it is irreflexive. But it is symmetric: if Ana is Ben’s sibling, Ben is Ana’s. Lemma 2 says a strict partial order never has both \(x \prec y\) and \(y \prec x\). (Transitivity also fails: Ana ≺ Ben and Ben ≺ Ana would force Ana ≺ Ana.) Checking irreflexivity alone is not enough.
Test each candidate against both axioms. A single counterexample to either one rules it out.
For a symmetric relation, apply transitivity to \(x \prec y\) and \(y \prec x\).

Only “proper subset” passes both axioms. ≤ fails irreflexivity; “beats” fails transitivity; “sibling” is symmetric, so transitivity would give someone as their own sibling.

Q2

Someone proposes to “fix” rock–paper–scissors by adding every pair that transitivity demands. What happens?

  • It becomes a strict partial order with exactly one sorted arrangement.
    Adding pairs cannot remove the cycle. Transitivity along rock ≺ scissors ≺ paper ≺ rock eventually demands rock ≺ rock.
  • Adding the implied pairs eventually forces rock ≺ rock, so it can never become a strict partial order.
    This is Lemma 3 run backwards: the closure of a relation with a cycle contains \(x \prec x\). A cycle cannot be repaired by adding constraints, only by removing one.
  • It becomes a strict partial order with several sorted arrangements.
    Every added pair is consistent with the cycle; following them around it forces some \(x \prec x\), which irreflexivity forbids.
  • It becomes a strict total order.
    After closing under transitivity every pair is related in both directions, including each element with itself. That violates irreflexivity and asymmetry.

Rock ≺ scissors and scissors ≺ paper demand rock ≺ paper; with paper ≺ rock that demands rock ≺ rock. Once a cycle exists, adding constraints only makes the contradiction explicit.

04Picturing a partial order, and counting its answers

(A), (B) and (C) are strict partial orders, and each has at least one answer. Two questions are open. Does every strict partial order have an answer? And how many answers does it have: (C) has five and (B) has two? In §01 we counted by hand. To count in general, and to prove that the count is never zero, we need two tools: a compact picture of a partial order, and a precise version of the question “which items can go first?”.

The picture first. The lists of Table 1 are long and repetitive. Once a list contains \(x \prec y\) and \(y \prec z\), it must also contain \(x \prec z\), by transitivity, and drawing that third pair adds nothing. A good picture shows only the pairs that no others imply: the direct steps, where one element comes immediately after another with nothing required in between.

Definition (covering pair, Hasse diagram)

\(y\) covers \(x\) if \(x \prec y\) and there is no \(z\) with \(x \prec z \prec y\). The Hasse diagram of \(\prec\) (named after the mathematician Helmut Hasse) draws each element as a node, places \(y\) above \(x\) whenever \(y\) covers \(x\), and joins them with a line.

Nothing is lost by drawing only the covering pairs: \(x \prec y\) holds exactly when there is an upward path of lines from \(x\) to \(y\) proof sketch. (If \(x \prec y\) and \(y\) does not cover \(x\), some \(z\) lies between them; split at \(z\) and repeat. Each split lengthens a chain of distinct elements, which cannot go on forever in a finite set, because a chain cannot revisit an element without forming a cycle.) Fig. 3 draws the tasks of (C).

Now the count. A sorted arrangement of a partial order is a single line-up of all its elements that respects every requirement. It extends partial information (some pairs settled, some not) to a complete line, and that is where its name comes from.

Definition (linear extension, e(P))

A linear extension of a strict partial order \(P\) is a sorted arrangement of its elements. We write \(e(P)\) for the number of linear extensions.

For the tasks, \(e(P) = 5\), and the five are listed under Fig. 3: the same five that §01 found by hand.

Does every strict partial order have at least one linear extension? (A), (B) and (C) do, but three examples are not a proof. §01 suggests how to build one: repeatedly choose an item that can go first. An item can go first exactly when nothing is required before it, and such an item has a name.

Definition (minimal element)

\(m\) is minimal if there is no \(x\) with \(x \prec m\).

Minimal does not mean “smallest”. The tasks have two minimal elements, a and b, and neither is below the other. A minimal element is only an element with nothing below it.

The procedure works only if a minimal element always exists. Could a partial order have none, with every element having something below it? That is exactly what happened in (D), but (D) is a cycle. Without cycles it cannot happen:

Lemma 4 (minimal elements exist)

Every strict partial order on a finite nonempty set has a minimal element.

Proof

Start at any element. If it is not minimal, some element is below it; move there, and repeat. The walk never revisits an element: if it did, the elements visited in between, read in reverse, would form a cycle (or give \(x \prec x\)), which Lemma 3 (or irreflexivity) rules out. A finite set has only finitely many elements to visit, so the walk stops, and it can only stop at a minimal element.

With Lemma 4, the procedure of §01 becomes a proof.

Theorem 5 (linear extensions exist)

Every strict partial order on a finite set has at least one linear extension.

Proof

Induction on the number of elements \(n\). For \(n \le 1\) there is nothing to prove. For \(n \ge 2\), choose a minimal element \(m\) (Lemma 4) and put it first. The remaining \(n-1\) elements, with \(\prec\) restricted to them, still form a strict partial order (restricting keeps irreflexivity and transitivity), so by induction they have a linear extension \(L'\). The arrangement \(m, L'\) is sorted: pairs inside \(L'\) are fine, and no element of \(L'\) is required before \(m\) because \(m\) is minimal.

Read it back: the proof is the procedure of §01, “repeatedly choose an item that can go first”, and it works for every partial order. It comes back in lesson 35, where it becomes an algorithm.

The procedure also explains why §01’s counting was right. The first element of any sorted arrangement must be minimal: if something were below it, that element would stand later and be required earlier, an out-of-order pair. The same holds for the second element among the rest, and so on. So every sorted arrangement arises from exactly one run of choices, each choice a minimal element of what remains, and every run produces a sorted arrangement (Theorem 5). Hence \(e(P)\) is exactly the number of paths through the choice tree of Fig. 1 proof.

Together, §03 and this section answer the question of §03 completely: a rule has an answer exactly when it has no cycle.

Corollary 6

A relation has a sorted arrangement if and only if it has no cycle.

Proof

If it has a cycle, Lemma 1. If it has no cycle, add every pair that transitivity demands. The result is transitive by construction, and irreflexive because \(x \prec x\) could only arise from a cycle through \(x\). By Theorem 5 it has a linear extension; that arrangement respects every original pair too, since the original pairs are among those added to.

Fig. 4 lets you build partial orders and watch the count change.

Going deeper · The fewest requirements that leave one order

Challenge 3 needs exactly \(n - 1 = 4\) requirements for 5 elements proof. Four suffice: a chain \(x_0 \prec x_1 \prec \cdots \prec x_4\). Fewer cannot work. First, if \(e(P) = 1\) the order is total: if \(x\) and \(y\) were unrelated, requiring \(x \prec y\) would create no cycle (a cycle through the new pair would need \(y \prec x\) already), so by Corollary 6 some valid order puts \(x\) before \(y\); symmetrically some puts \(y\) before \(x\); that is two orders. So the order is total, and its Hasse diagram is a single chain with \(n - 1\) covering pairs. A covering pair can never be implied by other pairs (anything implying \(x \prec y\) would need some \(z\) between them), so each of those \(n-1\) pairs must have been required directly. This “the picture needs \(n-1\) lines” argument returns in lesson 5, where it becomes a lower bound on the cost of checking that an array is sorted.

05When every pair is related

(A) has exactly one sorted arrangement and (C) has five. Which property of a rule forces a single answer?

Look at where the choices in (C) come from. At the start, a and b may go in either order; later, c and d may, and so may a and d (bdac is valid). Every choice involves a pair the rule leaves unconstrained. In (A) there is no such pair: of any two numbers, one is smaller. So a natural guess is that a rule with no unconstrained pairs leaves no choice at all. Such a rule is called total, because it settles every pair.

Definition (strict total order)

A strict partial order is total if every two distinct elements are related: for \(x \ne y\), either \(x \prec y\) or \(y \prec x\).

The guess is right, and the proof shows exactly where the single answer comes from.

Theorem 7 (exactly one sorted arrangement)

A strict total order on a finite set has exactly one sorted arrangement. In it, \(x_0 \prec x_1 \prec \cdots \prec x_{n-1}\).

Proof

Existence is Theorem 5. For uniqueness, use induction on \(n\); for \(n \le 1\) it is clear. The first element of a sorted arrangement must be minimal (§04). In a total order a minimal element \(m\) is below every other element: for \(y \ne m\), either \(y \prec m\), impossible since \(m\) is minimal, or \(m \prec y\). Two different such elements \(m, m'\) would satisfy \(m \prec m'\) and \(m' \prec m\), which Lemma 2 forbids. So the first position is forced: it holds the minimum. The other \(n - 1\) elements form a strict total order, whose sorted arrangement is unique by induction. Finally, any two positions \(i < j\) are related (totality) and \(x_j \prec x_i\) is excluded, so \(x_i \prec x_j\).

Read it back in the language of §01: in a total order, exactly one item can go first at every step, namely the smallest of those that remain, so the choices never branch. Every later lesson sorts under a total order (or under the slight relaxation of §06), so “sorting” will always mean finding this one forced arrangement.

There is a second reward. Checking a row against the definition means examining every pair of positions, \(n(n-1)/2\) of them. In §02 we tried the cheap shortcut, “each item before the next”, and ties broke it. For a total order there are no ties, and the cheap test is enough:

Lemma 8 (neighbours suffice for total orders)

An arrangement of a strict total order is sorted if and only if \(x_i \prec x_{i+1}\) for every \(i = 0, 1, \ldots, n-2\).

Proof

If it is sorted, Theorem 7 gives \(x_i \prec x_{i+1}\). Conversely, suppose every neighbour pair satisfies \(x_i \prec x_{i+1}\). For \(i < j\), transitivity applied along \(x_i \prec x_{i+1} \prec \cdots \prec x_j\) gives \(x_i \prec x_j\), and asymmetry rules out \(x_j \prec x_i\). So no pair is out of order.

That is \(n - 1\) checks instead of \(n(n-1)/2\). It is the first time transitivity saves work, and it will not be the last. Does the saving survive in a partial order?

06Ties

(B) is not total: Ana and Cy are unrelated. Yet it is far more orderly than (C). Its unconstrained pairs are harmless ties between people of the same age, while the unconstrained pairs of (C) are what broke the neighbour test. What exactly is the difference, and does the neighbour test survive ties?

The difference lies in what “unrelated” means. In (B), unrelated means “the same age”, and that passes along: if Ana is unrelated to Cy and Cy is unrelated to Eve, all three are the same age, so Ana is unrelated to Eve. In (C) it does not pass along: d is unrelated to a, and a is unrelated to b, yet b ≺ d. Rules in which “unrelated” passes along get their own name.

Definition (strict weak ordering)

Write \(x \sim y\) when neither \(x \prec y\) nor \(y \prec x\) (in particular \(x \sim x\)). A strict partial order is a strict weak ordering if \(\sim\) is transitive: \(x \sim y\) and \(y \sim z\) imply \(x \sim z\).

“Weak” because it is weaker than total: it allows ties. Read \(x \sim y\) as “\(x\) and \(y\) tie”.

In a strict weak ordering, \(\sim\) behaves exactly like “same age”. Every element ties with itself (by irreflexivity), a tie goes both ways (by its definition), and ties pass along (by assumption). A relation with these three properties (reflexive, symmetric and transitive) is called an equivalence relation. It splits the elements into groups in which every member ties with every other, the way “same age” splits people into age groups. In a strict weak ordering these groups are called tiers. In (B) the tiers are {Dee}, {Ben} and {Ana, Cy}.

In (B) the tiers line up by age, {Dee} (22), then {Ben} (25), then {Ana, Cy} (30), and every member of an earlier tier comes before every member of a later one. Is that always so? Could one tier be partly before another, with some of its members before and some not? The definition rules this out:

Lemma 9 (tiers are totally ordered)

In a strict weak ordering, if \(x \prec y\) and \(y \sim y'\), then \(x \prec y'\); likewise if \(x \prec y\) and \(x \sim x'\), then \(x' \prec y\). Hence whether \(x \prec y\) depends only on the tiers of \(x\) and \(y\), and any two different tiers \(T, T'\) satisfy either “every element of \(T\) is below every element of \(T'\)” or the reverse.

Proof

Suppose \(x \prec y\), \(y \sim y'\), but not \(x \prec y'\). Then either \(y' \prec x\) or \(x \sim y'\). If \(y' \prec x\), then \(y' \prec x \prec y\) gives \(y' \prec y\), contradicting \(y \sim y'\). If \(x \sim y'\), then \(x \sim y' \sim y\) gives \(x \sim y\) by transitivity of \(\sim\), contradicting \(x \prec y\). The second statement is symmetric. For two different tiers, pick \(t \in T\), \(t' \in T'\): they are not \(\sim\), so one is below the other, and by the first part the same holds for every pair of representatives.

So the tiers line up in a total order \(T_1, T_2, \ldots, T_k\), and that settles which rows are sorted and how many there are.

Theorem 10 (counting with ties)

An arrangement of a strict weak ordering is sorted if and only if it lists all of \(T_1\), then all of \(T_2\), …, then all of \(T_k\), each tier in any internal order. Hence, if the tiers have sizes \(n_1, \ldots, n_k\), there are exactly \(n_1!\, n_2! \cdots n_k!\) sorted arrangements.

Proof

If an element of a later tier came before an element of an earlier tier, that pair would be out of order (Lemma 9). Conversely, if tiers appear in order, elements of the same tier are unrelated and never out of order, and elements of different tiers appear in the right order. Each tier’s internal order can be chosen independently, in \(n_i!\) ways.

Sanity checks: (B) has tiers of sizes 1, 1 and 2, so \(1! \cdot 1! \cdot 2! = 2\). A total order has every tier of size 1, so \(1\), which is Theorem 7 again.

And the neighbour test survives ties, in its corrected form. Not “each item strictly before the next”, which ties break, but “no neighbour pair out of order”:

Lemma 11 (neighbours suffice for strict weak orderings)

An arrangement of a strict weak ordering is sorted if and only if no neighbour pair is out of order: \(x_{i+1} \prec x_i\) for no \(i\).

Proof

Number the tiers \(1, \ldots, k\) in their order and let \(t(x)\) be the number of \(x\)’s tier. “\(x_{i+1} \prec x_i\) fails” means \(t(x_i) \le t(x_{i+1})\) (Lemma 9). If this holds for every neighbour pair, then \(t(x_0) \le t(x_1) \le \cdots \le t(x_{n-1})\), because \(\le\) on numbers is transitive. So tiers appear in order, and Theorem 10 says the arrangement is sorted. The converse is immediate.

The whole difference between (B) and (C) is this one property. In a strict weak ordering, “may come before” (that is, \(\not\succ\)) passes along, so neighbour checks chain into checks of every pair. In a general partial order it does not.

Here is a partial order on numbers that is not a strict weak ordering. Say \(x \prec y\) when \(y - x > 1\): “noticeably smaller”. It is irreflexive and transitive (if \(y - x > 1\) and \(z - y > 1\) then \(z - x > 2\)). But 1.0 ∼ 1.5 and 1.5 ∼ 2.2, while 1.0 ≺ 2.2. The arrangement 2.2, 1.5, 1.0 has no out-of-order neighbours (each step differs by less than 1) and is not sorted (1.0 ≺ 2.2). Keep this example: in lesson 2 you will watch Python’s own sort fall into exactly this trap.

Common question · Isn’t (B) just sorting the ages?

Yes. Assign each person their age; then \(p \prec q\) exactly when age(\(p\)) \(<\) age(\(q\)), and the tiers are the distinct ages. Every strict weak ordering arises this way from some “key”. That is the first theorem of lesson 2, and it is why sorting by a key always makes sense.

E5

Put the steps of the proof of Theorem 7 (a strict total order has exactly one sorted arrangement) in order, and exclude the false steps.

  1. The first element of any sorted arrangement must be minimal.
  2. In a total order, a minimal element lies below every other element.
  3. Two different elements cannot both lie below everything, by asymmetry, so the first position is forced.
  4. Removing that element leaves a strict total order on n − 1 elements, whose arrangement is forced by induction.
  5. The first element of any arrangement is minimal.
  6. In a partial order, the minimal element is unique.
The structure: the first position is forced (steps 1–3), then induction handles the rest (step 4).

Ledger

Established

  • Sorted arrangement: no pair of positions \(i < j\) with \(x_j \prec x_i\). (definition) §02
  • A strict partial order (irreflexive, transitive) is asymmetric and has no cycles. proof §03
  • A relation has a sorted arrangement iff it has no cycle; every finite strict partial order has a linear extension, built by repeatedly removing a minimal element. proof §04
  • A strict total order has exactly one sorted arrangement; its first element is forced to be the minimum. proof §05
  • In a strict weak ordering, the tiers are totally ordered and there are \(n_1! \cdots n_k!\) sorted arrangements. proof §06
  • Checking neighbours suffices for strict weak orderings (\(n - 1\) checks) proof §05–06, but not for general partial orders proof by counterexample §05.
