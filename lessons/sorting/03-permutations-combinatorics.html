Part I: Information, Order, and Computational Limits • Chapter 3

Permutations, Combinatorics, and Information Entropy

"Before an algorithm asks its first question, it faces a colossal universe of possible answers. To understand how much work an algorithm must do, we must measure the size of this universe and calculate the exact quantity of information required to navigate it."

3.1 The Combinatorial Nature of Sorting

In Chapter 2, we saw that an algorithm begins in total ignorance and gradually eliminates inconsistent orderings. But how many possible orderings exist in the first place?

Suppose we are given an array of $n$ distinct elements: $A = [x_0, x_1, \dots, x_{n-1}]$. We want to place them into $n$ sorted positions: $$\text{Position 0}, \quad \text{Position 1}, \quad \text{Position 2}, \quad \dots, \quad \text{Position } n-1$$

Let us count how many different full orderings could possibly exist using the fundamental rule of multiplication:

  1. For Position 0 (the smallest element), any of the $n$ elements could potentially belong there. There are $n$ choices.
  2. For Position 1, having chosen the first element, any of the remaining $n-1$ elements could belong there. There are $n-1$ choices.
  3. For Position 2, there are $n-2$ choices remaining.
  4. Continuing this process down to the final position, exactly 1 choice remains.

Multiplying these independent choices together yields the total number of possible permutations, denoted $n!$ (read "$n$ factorial"):

Definition 3.1 (The Symmetric Group $S_n$)

A permutation of a set of $n$ elements is a bijection $\pi : \{0, \dots, n-1\} \to \{0, \dots, n-1\}$. The set of all $n!$ permutations forms a mathematical group under function composition, called the symmetric group of degree $n$, denoted $S_n$: $$|S_n| = n! = n \times (n-1) \times (n-2) \times \dots \times 2 \times 1 \tag{3.1}$$

The Staggering Growth of $n!$

Beginners often underestimate how quickly $n!$ grows. It does not grow like a polynomial ($n^2$ or $n^3$); it outgrows even standard exponential functions like $2^n$.

Array Size ($n$) Number of Permutations ($n!$) Physical Comparison
$n = 3$ 6 Trivial to enumerate on paper.
$n = 4$ 24 The universe of our Chapter 2 interactive lab.
$n = 5$ 120 Larger than a standard deck of cards.
$n = 10$ 3,628,800 Over 3.6 million possibilities.
$n = 20$ $2.43 \times 10^{18}$ More than the number of seconds since the Big Bang (~$4.3 \times 10^{17}$ s).
$n = 60$ $8.32 \times 10^{81}$ Exceeds the total number of atoms in the observable universe (~$10^{80}$).

This combinatorial explosion immediately rules out brute-force algorithms. If an algorithm tried to test every permutation one by one to see which one was sorted, it could not sort even 25 elements before the sun burned out!

3.2 Sorting as an Identification Problem

This combinatorial reality allows us to reframe the entire problem of sorting:

Conceptual Reframing

Given an unsorted array of $n$ distinct elements, exactly one permutation $\pi^* \in S_n$ corresponds to the true sorted order.

Therefore, sorting is the problem of identifying one specific target item out of a pool of $n!$ candidates.

At the start of execution, all $n!$ permutations are viable suspects. Every time our algorithm compares two elements, it learns a fact that rules out some fraction of these suspects.

This brings us to a deep question: how much uncertainty does an algorithm face at the beginning, and how much information is needed to resolve it?

3.3 Quantifying Uncertainty: Information Entropy

In 1948, mathematician Claude Shannon founded Information Theory by answering a simple question: how do you mathematically measure the amount of information in an unknown state?

Suppose an event has $K$ equally likely possible outcomes, and you do not know which outcome will happen. The amount of "missing information"—or uncertainty—is defined as: $$H = \log_2(K) \text{ bits} \tag{3.2}$$

What Is a "Bit" in Plain English?

We often hear the word "bit" used to describe computer memory (a 0 or a 1). But in information theory, a bit has a much deeper meaning:

Definition 3.2 (A Bit of Information)

One bit of information is the amount of knowledge gained by receiving the answer to a single, perfectly balanced Yes/No question that cuts the number of remaining possibilities exactly in half.

For example:

  • If there are $K = 2$ possibilities (e.g. a coin flip), you need $\log_2(2) = 1$ bit of information (1 Yes/No question) to know the outcome.
  • If there are $K = 4$ possibilities, you need $\log_2(4) = 2$ bits (2 questions: $4 \to 2 \to 1$).
  • If there are $K = 8$ possibilities, you need $\log_2(8) = 3$ bits (3 questions: $8 \to 4 \to 2 \to 1$).

The Initial Entropy of Sorting

At the start of sorting an array of $n$ distinct elements, there are $K = n!$ possible orderings. Assuming we have no prior knowledge of the input distribution, each permutation is equally likely.

Therefore, the initial information entropy of the sorting problem is:

$$H(S_n) = \log_2(n!) \text{ bits} \tag{3.3}$$

Equation (3.3) is one of the most celebrated equations in computer science. It tells us the exact quantity of information that any comparison algorithm must extract from the data before it can declare the array sorted.

3.5 Analytical Exercises

Problem 3.1 — How Much Information Is Learned by Finding the Minimum?
Suppose someone tells you which of the $n$ elements is the absolute minimum, but tells you nothing about the relative order of the remaining $n-1$ elements.
  1. How many of the original $n!$ permutations are still consistent with this knowledge?
  2. How many bits of information did you gain from this single fact?

Derivation:

1. Once the minimum element is fixed at Position 0, the remaining $n-1$ elements can be arranged in any of the $(n-1)!$ possible orders. Therefore, exactly $(n-1)!$ permutations remain.

2. The information gained is the difference between the initial entropy and the remaining entropy: $$\Delta H = H_{\text{initial}} - H_{\text{remaining}} = \log_2(n!) - \log_2((n-1)!)$$ Using the logarithmic identity $\log(A) - \log(B) = \log(A/B)$: $$\Delta H = \log_2\left(\frac{n!}{(n-1)!}\right) = \log_2\left(\frac{n \times (n-1)!}{(n-1)!}\right) = \log_2(n) \text{ bits}$$

Conclusion: Learning the identity of the minimum element yields exactly $\log_2 n$ bits of information. ■

Problem 3.2 — Proving That $n!$ Outgrows $2^n$
Prove by mathematical induction that for all integers $n \ge 4$: $$n! > 2^n$$

Proof:

Base Case ($n = 4$):
$$4! = 24, \quad 2^4 = 16$$ Since $24 > 16$, the base case holds.

Inductive Step:
Assume the induction hypothesis holds for some integer $k \ge 4$, so $k! > 2^k$. We must prove that $(k+1)! > 2^{k+1}$.

By definition of the factorial: $$(k+1)! = (k+1) \times k!$$ Applying the induction hypothesis $k! > 2^k$: $$(k+1)! > (k+1) \times 2^k$$ Since $k \ge 4$, we know that $k + 1 \ge 5 > 2$. Therefore: $$(k+1) \times 2^k > 2 \times 2^k = 2^{k+1}$$ Thus, $(k+1)! > 2^{k+1}$, completing the induction step. ■

Summary & Transition

In this chapter, we established:

  • Sorting is the problem of identifying 1 correct permutation out of $n!$ candidates.
  • The number of permutations grows factorially, quickly exceeding astronomical numbers.
  • The initial uncertainty of any comparison sorting problem is measured by its Shannon entropy: $$H = \log_2(n!) \text{ bits}$$
